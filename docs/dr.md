# 灾备与恢复手册（DR）

覆盖 Postgres、对象存储、API/Worker 的备份、恢复顺序、校验与演练。适用于交付/归档上线后的生产形态；本地 compose 只是恢复演练的替身。

## 1. 目标与假设

| 指标 | 目标 | 依据 |
|---|---|---|
| RPO（数据库） | ≤ 5 分钟 | WAL 归档 + 持续 PITR |
| RPO（对象存储） | ≤ 24 小时 | 版本化 + 每日跨区域复制；开启对象锁时按锁策略 |
| RTO（单区域故障，有热备） | ≤ 4 小时 | 数据库 PITR + 对象存储切换 + 服务拉起 |
| RTO（单区域故障，无热备） | ≤ 12 小时 | 从异地备份重建 |

假设：

- 生产使用托管 Postgres（或同等级自建：流复制 + WAL 归档）与兼容 S3 的对象存储（MinIO/云厂商）。
- 密钥（JWT、支付/电子签回调、存储、告警 webhook）存放在密钥管理系统，不随备份文件流转。
- **恢复环境禁止使用 sandbox 支付/电子签适配器处理真实资金/合同**；恢复后先以只读/停收款状态验证。

## 2. 需要备份的东西

| 资产 | 方式 | 频率 | 校验 |
|---|---|---|---|
| Postgres | 每日基础备份 + WAL/PITR（或托管自动备份） | 连续 WAL，每日全量 | 每周随机时间点恢复到演练库并跑 `go test`/`smoke` |
| 对象存储 | bucket 版本化 + 跨区域复制（`mc mirror --overwrite` 到异地） | 实时版本化，复制每日 | 每月抽样 `mc stat` + SHA-256 对比 `assets.content_hash` / `archive_items.expected_sha256` |
| 配置与密钥 | 密钥管理 + 配置仓库（不含明文密钥） | 变更即审 | 恢复演练时验证可注入 |
| 邮件队列 | 随数据库备份 | 同数据库 | `email_messages` 中 `body_text` 发送后已清空，属预期 |

对象存储单独备份的理由：数据库只存 key 与哈希；对象丢失时数据库无法重建原片、交付包、合同文件。

## 3. 恢复顺序

原则：先恢复「真相」（数据库）与「字节」（对象），再启动会产生新写入的组件（worker、API），最后验证业务闸门。

1. **冻结**：停止 API 与 worker（避免恢复期间继续消费队列、签发链接）；通知值班与客户成功。
2. **基础设施**：起 Postgres 与对象存储（空库/空桶）。
3. **数据库 PITR**：恢复到事故前最后一个已知良好时间点。选择时间点时注意：已发出的下载授权（`download_tokens`）与归档删除状态都会随之回滚。
4. **迁移校验**：`server/bin/migrate status`，确认版本（生产应为 0019 或更高）；**不要**在有数据时执行 0019 down。
5. **对象存储恢复**：按 bucket 复制/版本回滚，优先级：
   1. 原图（`assets.original_key`）
   2. 审片修图源与派生（`asset_revisions`、`asset_derivatives`）
   3. 交付包与 web 文件（`delivery_packages.object_key`、`delivery_items.web_object_key`）
   6. 合同/签署件、发票文件
   恢复后抽样比对 SHA-256（`archive_items` 的 `expected_sha256` 可直接用作清单）。
6. **启动 worker**：先小批量（`WORKER__BATCH_SIZE` 调低）。历史 `delivery.*`/`archive.*` 任务若已成功会在恢复后按 `jobs` 状态续跑；卡在 `running` 的租约会过期后被重新领取。
7. **启动 API**：确认 `PWF_ENV=production` 且适配器为正式渠道；健康检查与只读接口先行。
8. **安全动作（必须）**：
   - 撤销所有未过期下载链接：`UPDATE download_tokens SET revoked_at = now() WHERE revoked_at IS NULL;`（同时写审计说明），再逐个客户重新签发。
   - 轮换 JWT/回调/存储密钥（若怀疑泄露）。
   - 检查 `audit_logs` 与 `payment_alerts` 中恢复窗口内的异常。

## 4. 恢复后校验

按顺序执行，任一步失败即停止并回退决策：

1. `GET /healthz`、`GET /readyz`（如启用）。
2. 登录与只读接口：项目列表、交付列表、通知列表。
3. **交付链路**：对一个测试项目走 `smoke`（`make smoke` 或 `server/bin/smoke -base ...`），确认未付款闸门、构建、下载、撤销、退款失效。
4. **归档链路**：对测试项目执行归档核验，确认 `verified_count = object_count`，`retention_until` 合理。
5. **对象抽检**：随机 20 个 `archive_items`，`mc stat` 比对大小，`mc cat | sha256sum` 比对 `expected_sha256`。
6. **队列健康**：`SELECT kind, status, count(*) FROM jobs WHERE created_at > now() - interval '1 hour' GROUP BY 1,2;` 无持续 `dead`。
7. **资金安全**：确认支付回调地址指向恢复后的环境；在完成验证前保持收款关闭或使用测试渠道。

## 5. 演练清单

每季度至少一次，记录在本文件或工单：

- [ ] 从备份 PITR 恢复到临时库，耗时记录（目标 ≤ 4h）。
- [ ] 对象存储从异地副本恢复一个项目（原图 + 交付包 + 合同），SHA-256 全对。
- [ ] 起 API/worker 跑 `smoke`（M0–M7）全绿。
- [ ] 归档核验与保留计算正确；删除流程**不**在演练中真实执行（除非用独立测试桶）。
- [ ] 撤销交付链接脚本演练（记录执行人与审计条目）。
- [ ] 密钥轮换演练（JWT/回调/存储）。

## 6. 已知边界

- **预签名 URL**：撤销 token 后，撤销前签发的 URL 最长仍可使用 `delivery.presign_ttl`（默认 5 分钟）。恢复演练与事故处置时应意识到这段窗口。
- **限流是进程内**：多副本部署时，恢复后限流状态不共享；交付客户接口的 120/min 与 30/min 仅单实例生效。需要全局限流时在网关层实现。
- **删除不可逆**：归档删除会真实删除对象；数据库行保留墓碑。对象存储版本化是唯一恢复路径。
- **队列不保存业务快照**：`jobs` 只存参数；恢复后若引用的对象已丢失，任务会失败并告警——这属于预期，按 runbook 修复源对象后重试。
- **邮件正文**：发送成功后 `body_text` 已清空；恢复后无法补发历史正文，只能重新通知客户（重新签发 token 会生成新链接）。
